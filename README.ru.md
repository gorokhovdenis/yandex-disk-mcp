# Yandex.Disk MCP Server

[English](README.md) | **Русский**

MCP-сервер для работы с REST API Яндекс.Диска из Claude и других MCP-клиентов.

## Возможности

- 📊 Информация о диске: общий и занятый объём
- 📁 Список файлов и папок
- 📄 Метаданные файла или папки, с постраничным выводом для больших папок
- 🔍 Сравнение локальной папки с папкой на Диске: рекурсивно, по размеру и при желании по MD5
- ➕ Создание папок
- ⬆️ Загрузка файлов и папок фоновой задачей: с докачкой, проверкой MD5 и без ограничения скорости для видео
- 🔗 Ссылка на загрузку для собственного загрузчика
- ⬇️ Скачивание файлов и папок на локальный диск фоновой задачей: с проверкой MD5 и сохранением дат изменения
- 🔗 Ссылка на скачивание для собственного загрузчика
- 🗑️ Удаление файлов и папок
- 📋 Копирование файлов и папок
- 🔄 Перемещение и переименование
- 🕐 Последние загруженные файлы

## Что нужно

- Node.js 18 или новее
- OAuth-токен Яндекс.Диска

## Как получить OAuth-токен

1. Откройте [Яндекс OAuth](https://oauth.yandex.ru/client/new)
2. Создайте новое приложение
3. Выберите права:
   - `cloud_api:disk.read` — чтение файлов
   - `cloud_api:disk.write` — запись файлов
   - `cloud_api:disk.info` — информация о диске
4. Скопируйте Client ID
5. Откройте в браузере ссылку, подставив свой Client ID вместо `<CLIENT_ID>`:
   ```
   https://oauth.yandex.ru/authorize?response_type=token&client_id=<CLIENT_ID>
   ```
6. Скопируйте токен со страницы авторизации
7. Сохраните его в надёжном месте

## Установка

### Вариант 1: из npm (рекомендуется)

```bash
npm install -g yandex-disk-mcp
```

### Вариант 2: из GitHub

```bash
git clone https://github.com/gorokhovdenis/yandex-disk-mcp.git
cd yandex-disk-mcp
npm install
npm run build
```

## Настройка

Добавьте сервер в конфигурацию Claude Code (`~/.claude.json`):

```json
{
  "mcpServers": {
    "yandex-disk": {
      "type": "stdio",
      "command": "node",
      "args": ["/path/to/yandex-disk-mcp/dist/index.js"],
      "env": {
        "YANDEX_DISK_TOKEN": "your_oauth_token_here"
      }
    }
  }
}
```

**Важно:** замените `/path/to/yandex-disk-mcp` на путь, куда склонирован репозиторий.

Необязательно: переменные `YANDEX_DISK_UPLOAD_PROXY` и `YANDEX_DISK_DOWNLOAD_PROXY` в `env` (например, `http://127.0.0.1:8078`) пускают через HTTP-прокси трафик `yandex_disk_upload` и `yandex_disk_download` соответственно. Запросы к API всегда идут напрямую.

## Инструменты

### yandex_disk_info
Информация о Диске: общий объём, занято, в корзине и т. д.

**Параметры:** нет

**Пример:**
```
Claude, сколько места на моём Яндекс.Диске?
```

### yandex_disk_list_files
Плоский список всех файлов на Диске.

**Параметры:**
- `limit` (number, необязательный): сколько файлов вернуть (по умолчанию 20)
- `offset` (number, необязательный): смещение для постраничного вывода (по умолчанию 0)

**Пример:**
```
Claude, покажи 50 файлов с моего Яндекс.Диска
```

### yandex_disk_get_metadata
Метаданные файла или папки. Для папки в `_embedded.items` лежит одна страница содержимого, а в `_embedded.total` — общее число элементов.

**Параметры:**
- `path` (string, обязательный): путь к файлу или папке, например `'/Documents/file.txt'`
- `limit` (number, необязательный): элементов папки на страницу (по умолчанию 20)
- `offset` (number, необязательный): смещение в списке папки (по умолчанию 0)

**Пример:**
```
Claude, покажи метаданные /Documents/report.pdf на Яндекс.Диске
```

### yandex_disk_compare
Рекурсивно сравнивает локальную папку с папкой на Диске. Например, чтобы проверить, что бэкап на внешнем диске совпадает с копией в облаке.

Файлы сопоставляются по относительному пути и размеру, при желании ещё и по MD5. Пути приводятся к NFC, поэтому имена с «й» и «ё» из macOS совпадают с облачными. Удалённые папки читаются параллельно, на 429 и 5xx запрос повторяется.

**Параметры:**
- `remote_path` (string, обязательный): папка на Диске, например `'/Backups/Photos'`
- `local_path` (string, обязательный): абсолютный путь к локальной папке, например `'/Volumes/USB/Photos'`
- `check_md5` (boolean, необязательный): сравнивать ещё и MD5 у файлов одного размера. Каждый такой файл читается целиком, поэтому на больших папках это долго (по умолчанию false)
- `ignore` (string[], необязательный): маски имён файлов и папок, которые пропускаются с обеих сторон (по умолчанию `['.DS_Store', '._*']`)
- `max_items` (number, необязательный): сколько записей возвращать в каждом списке (по умолчанию 100)
- `output_file` (string, необязательный): локальный путь, куда записать полный отчёт в JSON без обрезки

**Возвращает:** итоги по обеим сторонам; счётчики `matching`, `only_local`, `only_remote`, `size_mismatch`, `md5_mismatch` и `case_mismatch` (имена отличаются только регистром); расхождения по папкам верхнего уровня; сами списки, обрезанные до `max_items` (что обрезано — видно в `truncated`).

**Пример:**
```
Claude, сравни /Volumes/USB/Photos с /Photos на Яндекс.Диске
```

### yandex_disk_create_folder
Создаёт папку.

**Параметры:**
- `path` (string, обязательный): путь новой папки, например `'/Documents/NewFolder'`

**Пример:**
```
Claude, создай папку /Backups/2026 на Яндекс.Диске
```

### yandex_disk_upload
Загружает локальный файл или папку целиком в папку на Диске. Папка загружается рекурсивно, с сохранением структуры.

Загрузка идёт фоновой задачей внутри MCP-сервера, поэтому многогигабайтные загрузки не упираются в таймаут вызова. Инструмент ждёт `wait_seconds` и возвращает `job_id` с прогрессом. Дальше прогресс смотрят через `yandex_disk_upload_status`.

- Файлы, которые уже лежат на Диске с тем же размером, пропускаются. Поэтому повторный запуск той же загрузки просто продолжает её.
- Недостающие папки создаются.
- Каждый загруженный файл сверяется с локальным по MD5.
- **Видео загружается под временным именем `.part` и после загрузки переименовывается.** Яндекс.Диск ограничивает загрузку видео через API примерно до 130 КБ/с и, судя по всему, определяет видео по расширению в целевом пути: те же байты под другим именем идут на полной скорости. После переименования MD5 не меняется, Диск распознаёт файл как видео и читает дату из EXIF. Если от прерванной загрузки остался `.part` того же размера, он только переименовывается.
- **Перед переименованием инструмент ждёт обработки файла на стороне Диска** (до 60 с, обычно несколько секунд). Превью и дату съёмки Диск делает асинхронно, уже после загрузки, и записывает результат по пути файла. Если переименовать раньше, результат попадёт на старый путь: там снова появится «призрачный» `.part`, а у переименованного файла не будет даты, и в ленте Фото он окажется не на своём месте. Если за 60 с ни превью, ни дата не появились, файл всё равно переименовывается, а в логе об этом остаётся пометка.
- Задача живёт в процессе сервера. Если MCP-клиент перезапустит сервер, задача остановится; чтобы продолжить, достаточно повторить тот же вызов.

**Параметры:**
- `local_path` (string, обязательный): абсолютный путь к локальному файлу или папке
- `remote_path` (string, обязательный): папка назначения на Диске, например `'/Photo/2017'`; если её нет, она будет создана
- `include` (string[], необязательный): загрузить только эти файлы. Пути относительно `local_path` (как в `only_local` из `yandex_disk_compare`) или абсолютные
- `overwrite` (boolean, необязательный): заменять существующие файлы. При false файл того же размера пропускается, а файл другого размера попадает в ошибки (по умолчанию false)
- `ignore` (string[], необязательный): маски имён, которые пропускаются при обходе папки (по умолчанию `['.DS_Store', '._*']`)
- `bypass_extensions` (string[], необязательный): расширения, которые загружаются через временное имя `.part`. По умолчанию — распространённые видеоформаты: mp4, mov, m4v, avi, mkv, 3gp, wmv, webm, mts, m2ts, mpg, mpeg, flv. `[]` отключает обход
- `concurrency` (number, необязательный): сколько файлов грузить параллельно, от 1 до 4 (по умолчанию 1)
- `proxy` (string, необязательный): HTTP-прокси для трафика загрузки, например `'http://127.0.0.1:8078'`. По умолчанию берётся `YANDEX_DISK_UPLOAD_PROXY`; `''` отключает прокси
- `log_file` (string, необязательный): локальный файл, куда дописывается строка на каждый файл (`OK` / `SKIP` / `FAIL`). Удобно следить через `tail -f`
- `wait_seconds` (number, необязательный): сколько секунд ждать завершения перед ответом, от 0 до 900 (по умолчанию 30)

**Возвращает:** статус задачи (см. ниже).

**Пример:**
```
Claude, загрузи /Volumes/USB/DCIM/Camera в /Photo/2017 на Яндекс.Диске
```

### yandex_disk_upload_status
Прогресс задачи загрузки: счётчики файлов (`done`, `skipped`, `failed`, `pending` и др.), байты, средняя скорость, оставшееся время, файлы в процессе загрузки и ошибки. Без `job_id` выводит все задачи текущего процесса сервера.

**Параметры:**
- `job_id` (string, необязательный): номер задачи из ответа `yandex_disk_upload`
- `wait_seconds` (number, необязательный): сколько секунд ждать завершения перед ответом, от 0 до 900 (по умолчанию 0)
- `max_items` (number, необязательный): сколько записей возвращать в каждом списке (по умолчанию 50)

### yandex_disk_upload_cancel
Отменяет задачу загрузки. Файлы, которые грузятся в этот момент, обрываются: незавершённая загрузка ничего не оставляет на Диске. Уже загруженные файлы остаются.

**Параметры:**
- `job_id` (string, обязательный): номер задачи из ответа `yandex_disk_upload`

### yandex_disk_get_upload_url
Ссылка на загрузку файла своим клиентом (curl и т. п.). Обычно проще `yandex_disk_upload`.

**Параметры:**
- `path` (string, обязательный): куда загрузить файл
- `overwrite` (boolean, необязательный): перезаписать, если файл уже есть (по умолчанию true)

**Пример:**
```
Claude, дай ссылку на загрузку /Documents/report.pdf на Яндекс.Диск
```

### yandex_disk_download
Скачивает с Диска файл или целую папку, рекурсивно и с сохранением структуры, в локальную папку. Подходит, например, для локального бэкапа.

Как и загрузка, работает фоновой задачей: инструмент ждёт `wait_seconds` и возвращает `job_id` с прогрессом. Дальше прогресс смотрят через `yandex_disk_download_status`.

- Файлы, которые уже лежат на локальном диске с тем же размером, пропускаются. Поэтому повторный запуск продолжает скачивание с места остановки.
- Недостающие локальные папки создаются.
- Каждый файл пишется как `<имя>.part` и переименовывается, только когда его размер и MD5 совпали с Диском. Недокачанный файл никогда не выглядит готовым.
- У скачанных файлов сохраняется дата изменения с Диска: когда файл туда загрузили или изменили, а не дата съёмки.
- Если сервер хранения 30 секунд ничего не присылает, попытка обрывается и повторяется с новой ссылкой, всего до 3 попыток. У Диска бывает сервер хранения, который принимает запросы к части файлов и молчит, хотя другие файлы приходят за секунду. Такие файлы попадают в `failed`, их докачивает повторный запуск того же скачивания позже.
- Если на локальном томе меньше свободного места, чем нужно для скачивания, задача не запускается.
- Ссылку на скачивание папки целиком Диск не выдаёт (API отвечает 500), поэтому инструмент обходит папку и качает файлы по одному.

**Параметры:**
- `remote_path` (string, обязательный): файл или папка на Диске, например `/Photo/2004`
- `local_path` (string, обязательный): абсолютный путь к локальной папке, куда ляжет содержимое `remote_path`, например `/Volumes/Backup/Photo/2004`; создаётся, если её нет
- `overwrite` (boolean, необязательный): заменять локальные файлы. Если false, файл того же размера пропускается, а файл другого размера попадает в ошибки (по умолчанию false)
- `ignore` (string[], необязательный): маски имён файлов и папок, которые пропускаются при обходе папки на Диске (по умолчанию `['.DS_Store', '._*']`)
- `concurrency` (number, необязательный): сколько файлов качать параллельно, 1–8 (по умолчанию 4)
- `proxy` (string, необязательный): HTTP-прокси для трафика скачивания, например `http://127.0.0.1:8078`. По умолчанию `YANDEX_DISK_DOWNLOAD_PROXY`; `''` отключает
- `log_file` (string, необязательный): локальный файл, куда дописывается строка на каждый файл (`OK` / `SKIP` / `FAIL`)
- `wait_seconds` (number, необязательный): сколько секунд ждать завершения перед ответом, 0–900 (по умолчанию 30)

**Возвращает:** состояние задачи, в том же виде, что и у загрузки.

**Пример:**
```
«Скачай /Photo с Яндекс.Диска в /Volumes/Backup/Photo»
```

### yandex_disk_download_status
Прогресс скачивания: сколько файлов скачано, пропущено, с ошибкой, объём, средняя скорость, оставшееся время, файлы в работе и ошибки. Без `job_id` показывает все задачи скачивания этого процесса.

**Параметры:**
- `job_id` (string, необязательный): `job_id`, который вернул `yandex_disk_download`
- `wait_seconds` (number, необязательный): сколько секунд ждать завершения перед ответом, 0–900 (по умолчанию 0)
- `max_items` (number, необязательный): сколько записей максимум в каждом списке ответа (по умолчанию 50)

### yandex_disk_download_cancel
Отменяет скачивание. Файлы в работе прерываются, их `.part` удаляются; уже скачанные остаются.

**Параметры:**
- `job_id` (string, обязательный): `job_id`, который вернул `yandex_disk_download`

### yandex_disk_get_download_url
Ссылка на скачивание файла своим клиентом. Для целых папок проще `yandex_disk_download`.

**Параметры:**
- `path` (string, обязательный): путь к файлу

**Пример:**
```
Claude, дай ссылку на скачивание /Documents/report.pdf с Яндекс.Диска
```

### yandex_disk_delete
Удаляет файл или папку.

**Параметры:**
- `path` (string, обязательный): путь к файлу или папке
- `permanently` (boolean, необязательный): удалить насовсем (true) или в корзину (false, по умолчанию)

**Пример:**
```
Claude, удали /temp/old_file.txt с Яндекс.Диска
```

### yandex_disk_copy
Копирует файл или папку.

**Параметры:**
- `from` (string, обязательный): откуда
- `to` (string, обязательный): куда
- `overwrite` (boolean, необязательный): перезаписать, если путь назначения занят (по умолчанию true)

**Пример:**
```
Claude, скопируй /Documents/file.txt в /Backups/file.txt на Яндекс.Диске
```

### yandex_disk_move
Перемещает или переименовывает файл или папку.

**Параметры:**
- `from` (string, обязательный): откуда
- `to` (string, обязательный): куда
- `overwrite` (boolean, необязательный): перезаписать, если путь назначения занят (по умолчанию true)

**Пример:**
```
Claude, перенеси /temp/file.txt в /Documents/file.txt на Яндекс.Диске
```

### yandex_disk_last_uploaded
Последние загруженные файлы.

**Параметры:**
- `limit` (number, необязательный): сколько файлов вернуть (по умолчанию 10)

**Пример:**
```
Claude, покажи 20 последних загруженных файлов на Яндекс.Диске
```

## Примеры

После настройки с Claude можно говорить обычным языком:

1. **Проверить место:**
   ```
   «Сколько свободного места на Яндекс.Диске?»
   ```

2. **Загрузить файлы:**
   ```
   «Загрузи /Users/me/Desktop/report.pdf в /Documents на Яндекс.Диске»
   ```

3. **Навести порядок:**
   ```
   «Создай папку /Projects/2026 и перенеси туда все файлы из /temp на Яндекс.Диске»
   ```

4. **Сделать бэкап:**
   ```
   «Скопируй все .md из текущей папки в /Backups на Яндекс.Диске»
   ```

5. **Проверить бэкап:**
   ```
   «Сравни /Volumes/USB/Archive с /Archive на Яндекс.Диске и скажи, чего не хватает в облаке»
   ```

6. **Догрузить недостающее:**
   ```
   «Загрузи в /Archive файлы, которых нет в облаке»
   ```
   Claude передаёт `only_local` из сравнения в `include` для `yandex_disk_upload`.

7. **Локальный бэкап:**
   ```
   «Скачай /Photo с Яндекс.Диска в /Volumes/Backup/Photo»
   ```

